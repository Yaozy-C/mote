# Prototype Instructions

Run the local server yourself and open the preview in the browser available to this environment. Do not give the user server-start instructions when you can run it.

Before making substantial visual changes, use the Product Design plugin's `get-context` skill when the visual source is unclear or no longer matches the current goal. When the user gives durable prototype-specific design feedback, preferences, or decisions, record them in `AGENTS.md`.

When implementing from a selected generated mock, treat that image as the source of truth for layout, component anatomy, density, spacing, color, typography, visible content, and hierarchy.

## Mote visual direction

- Product name: Mote.
- Source visual: `public/assets/source-reference.png`.
- Preserve the warm luminous frosted-glass window, restrained coral selection/action color, content-rich preview, sparse ambient particles, precise desktop typography, and calm premium feel.
- The primary flow is search history, select an item, inspect it, then copy, pin, or delete it.
- Selected redesign direction: a native-neutral macOS split view with an integrated titlebar/toolbar, system materials, compact information density, neutral colors, and macOS system blue for selection and focus. Avoid broad pink tint, card-heavy web UI, oversized controls, and format tabs.
- Motion should feel native and functional: short interruptible transitions for selection, search focus, detail changes, menus/dialogs, and action confirmation. Keep ambient motion nearly invisible and fully honor Reduce Motion.
- Keep the macOS titlebar minimal: show neither the app logo nor the app name beside the native traffic-light controls.
- Use Tabler Icons for the paste, pin, and delete action group, with consistent 18px sizing and 1.75px strokes; do not use a return-arrow icon to represent paste.
- In multiple-paste previews, show the actual queued content (text/URL/code/file names, image thumbnails, or color swatches) instead of record titles and type labels.
- The multiple-paste detail pane is content-adaptive: use large visual cards when images/colors dominate, a comfortable list for a few text records, and a scrollable list for larger queues. Its content region should consume the available pane height instead of leaving a fixed blank area.
- A “combined copy” means one clipboard change containing multiple ordered pasteboard items (for example text plus an image), not merely alternate formats of one value. Store it as one history record, preserve item order and native representations, preview the items together, and restore the whole structure when copied or pasted.
- Ambient particles must remain visible in the native Tauri window, use restrained coral/gold/cream tones, stay behind the working UI, and prefer a GPU shader path with reduced-motion and rendering-failure fallbacks.
- Do not expose alternate clipboard representations as format tabs. One clipboard change is one user-facing record; choose its richest representation automatically and show multiple ordered pasteboard items as one combined preview.
- Support macOS on Apple Silicon only. Keep the minimal integrated macOS titlebar, macOS-native shortcut labels, system materials, and publish DMG installers from GitHub Releases. Do not add Windows-specific runtime, UI, packaging, or release paths.
- Treat Settings as a transient popover: clicking anywhere outside it closes it immediately while preserving the outside click's intended action.
- User-facing safety is part of the core experience: show clipboard/Accessibility readiness, keep deletions recoverable with an immediate Undo action, flag file records whose original path is unavailable, and expose compact actions specific to links, files, colors, and images. Image previews should extract a small clickable palette whose color values can be copied.
- Permission readiness must refresh automatically when the native Mote window regains focus after System Settings, and while the Settings popover remains open. “Check again” must visibly show checking, success, or still-needs-access feedback instead of appearing unresponsive.
- If macOS still reports a permission as unavailable after the user enabled Mote, explain that an app update may have left a stale authorization and offer one explicit action to reset and re-request the permissions for the currently installed build. Never report readiness based only on the visible System Settings toggle; the native trust APIs remain authoritative.
- Color picking is a first-class global action, not an image-only extraction feature: a configurable shortcut should open the system screen color sampler, one click should copy and save the sampled color, and Escape should cancel.
- Help should behave like a compact Apple Tips guide rather than a single onboarding sheet: organize features by topic and give every major capability a visual example. Keep the main Settings popover concise and open keyboard-shortcut customization in its own focused dialog.
- Keep every transient surface task-first: omit decorative logos, subtitles, eyebrow labels, and duplicate dismissal controls when the title, content, or action already communicates the same thing. Prefer one compact status summary, reveal explanations only for exceptions, and avoid fixed dialog heights that leave unused space.
- Every titlebar icon action must have a consistent hover surface, immediate custom tooltip, keyboard-focus treatment, pressed feedback, and visible active state when it owns an open transient surface. Tooltips should name the action and include its configurable shortcut when one exists; disabled actions must still explain why they are unavailable.
- Distribute macOS builds through GitHub Releases. Mote should check the signed `latest.json` feed on launch, offer a manual check in Settings, show download progress, and restart only after a verified update is installed.
- Treat OCR text as derived metadata, never as a replacement for the captured image. An image record's default copy and paste actions must restore the original image; OCR text is searchable, visibly labeled, and available only through explicit secondary actions such as copy or paste recognized text.
- OCR formula detection is advisory. PP-OCR text may preserve characters but not mathematical structure, so show formula-like OCR as selectable raw text with a fidelity warning instead of presenting it as reliably rendered mathematics.
- Treat the right detail pane as a plugin host: typed content renderers declare their own support and render inside one compact, standardized section shell. Keep source files at 300 lines or fewer so new preview capabilities remain independently maintainable.
- Keep OCR presentation visually lightweight: use a flat secondary section in the detail pane with compact icon actions, selectable text, and an understated formula warning. Avoid nested cards, footer button rows, and visible engine metadata.
- Treat keyboard shortcuts as a first-class standalone tool opened directly from the titlebar. Keep shortcut recording and conflict feedback in its own focused dialog rather than nesting shortcut management inside Settings.
- Keep ordering and combined-output control inside the existing multiple-paste flow. The entire detail pane previews one combined clipboard change containing the selected text, images, files, and other native representations; users can reorder that preview, and the native paste operation must preserve the visible item order and types in one write.
- Treat screenshot capture as a first-class global tool modeled on WeChat's workflow: a configurable shortcut opens a frozen-screen selection overlay, hovering automatically recognizes and highlights whole windows, dragging always allows a freeform region, and the result can be annotated, copied, and saved directly into Mote history. Do not reduce this to merely invoking the macOS screenshot utility.
- The titlebar screenshot action and its global shortcut must enter a frozen native selection overlay immediately. Hover highlights the frontmost whole window; press and release without dragging selects that window; pressing and dragging switches to a freeform rectangular selection, and Escape cancels. Do not put a configuration, target, or permission-summary dialog in front of capture; surface permission failures only as exceptions.
- Make scrolling screenshots a first-class screenshot mode for long webpages and scrollable article views. Offer automatic scrolling as the preferred mode when Accessibility permission is available: scroll the selected surface in small steps, wait for content to settle, detect overlapping content, remove repeated fixed regions, show live stitching progress, and stop at the true end. Pause immediately on user input, lost focus, no visual progress, dynamic-content instability, or stitching uncertainty, and always provide user-controlled scrolling as the fallback. Use browser-native full-page capture when reliably available, but provide visual scroll-and-stitch as the cross-app fallback; never imply that every dynamic, protected, or virtualized surface can be stitched perfectly.

Build app UI in `src/`. Keep `.openai/hosting.json`, `worker/index.js`, `scripts/prepare-sites-build.mjs`, and `tests/sites-worker.test.mjs` intact so the same local prototype can be handed to Sites. Before a Sites handoff, run `npm run build` and `npm run test:sites`; the build must leave `dist/client/index.html`, `dist/server/index.js`, and `dist/.openai/hosting.json`.
